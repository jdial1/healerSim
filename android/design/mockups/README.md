# Party-frame mockups — VuhDo / HealBot idiom, TBC–WotLK dressing

Generated by `make-frames.py` (PIL). Three treatments of the same five-unit
fixture, so the differences are layout, not data.

| File | Treatment |
|---|---|
| `01-vuhdo-idiom.png` | Bar-is-the-cell. Name overlaid, debuff chip top-left, HoT chips bottom-right, percent right-aligned. 2px gaps. |
| `02-healbot-idiom.png` | Name left / value right, thin power strip under each bar, border colour carries dispel type. |
| `03-wotlk-stone-brass.png` | Same density as 01, dressed in stone + brass bevel with a recessed socket for the bar. |

## The point of the exercise

In VuhDo and HealBot the health bar **is** the cell. There is no card around it,
no separate title row, and rows sit 1–2px apart. Every element — name, value,
HoTs, debuffs — is overlaid on the bar or tucked into a corner, because a raid
frame is read at a glance and each pixel has to carry data.

Overheal's current row spends a meaningful fraction of its height on chrome
(card padding, border, a title line) that carries none. These mockups show what
the same information looks like when the bar absorbs it.

## What is actually adoptable

Adoptable now, no engine change:

- Percent + deficit overlaid on the bar (Phase 1.1 — already done).
- Debuff and HoT chips as small squares with a countdown numeral, in fixed
  corners rather than a flowing row. Fixed positions are why these frames do not
  change height when auras appear.
- Luminance-picked text colour with an outline. See `ink()` — a fixed white name
  is unreadable on a light bar and a fixed dark one is unreadable on a dark bar.
  The addons solve this with an outline; so does this.
- Tighter row gaps and no per-row card.

## What these mockups show but the game cannot honestly ship

Flagging these rather than quietly implying them:

- **Class-coloured bars.** The single most recognisable VuhDo cue, and out of
  scope by the approved plan: Overheal's party are generic NPCs with no class,
  so a class colour would be decoration pretending to be information. The
  colours here exist only to make five rows distinguishable in a mockup.
- **Dispel-type tinting on the name** (blue magic / purple curse / green
  poison). Same reason dispel highlighting was excluded from the plan: dispel is
  not wired, so the tint would advertise an action the player cannot take.
- **Aggro border** (row 1, red). There is no threat model — boss targeting is
  `single_random` / `two_random` / `all_living`.
- **Per-unit mana strip** (02). NPC party members have no mana in the sim.

The layout ideas survive without any of these; the colour semantics do not.

## 04 / 05 — the TBC/WotLK dressing, built out

`04-wotlk-auras.png` (wide) and `05-wotlk-auras-phone.png` (**to scale**, 1080px
= a 360dp phone at 3×) develop treatment 03 with auras as the second thing you
read after health.

**The aura rule.** Every aura is the same size, in the same fixed centre slot,
whatever it is. The ring is the whole signal:

- **Red ring + red bloom** — hostile. Something is hurting this unit.
- **Brass ring, no bloom** — friendly. A HoT or a shield.

Identical geometry either way is the point: the row height never moves when an
aura appears or falls off (the bug the earlier fix addressed), and the eye sorts
by colour instead of by position. Debuffs sort ahead of buffs inside the
cluster, so triage reads left to right.

Each socket carries a countdown numeral bottom-right and a stack count
top-left when stacks > 1 — `UnitBuff.stacks` and `UnitDebuff` remaining ticks,
both already in the model.

**The art is real.** Buffs use the game's own WoW icons (`public/icons/wow`);
debuffs use the game-icons glyphs the boss debuff templates actually reference
(`lorc/sunder-armor`, `lorc/skull-staff`, `lorc/vines` are Gut Slash, Curse of
Shadowfang and Strangling Roots). The glyphs are recoloured off their alpha
channel onto a dark plate, so they sit on a bar without a white box.

**It fits.** This is why 05 exists — the wide mockup does not answer the
question that decides the design. At 360dp × 3× the rows are 56dp with 30dp
icons; five rows plus gaps come to 936px of a ~2400px screen, leaving the enemy
frame and action bar the room they have today. Both are above the 48dp floor
the current layout already lives at.

Still subject to the caveats above: the class-coloured bars and the aggro border
on row 1 are mockup dressing, not shippable signal.
